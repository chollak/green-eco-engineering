# GREEN ECO ENGINEERING — сайт

Статический двуязычный (RU/UZ) сайт электромонтажной компании.
20 страниц: главная, каталог работ, 17 страниц направлений, 404.

**Продакшн:** https://chollak.github.io/green-eco-engineering/
(GitHub Pages, ветка `main`, корень репозитория)

## Сборка

```bash
node build.mjs
```

HTML в корне — **артефакт сборки**. Править его руками бессмысленно: перезапишется.
Сборка падает, если в разметку просочился абсолютный путь `/...` — на Pages сайт живёт
по подпути, такие ссылки ломаются.

Каждый текст — пара `{ ru, uz }`. Переключатель языка подменяет содержимое из `data-uz`
без перезагрузки, выбор хранится в `localStorage`.

**Узбекские апострофы:** `o‘`/`g‘` — U+2018, `ta’mir` — U+2019.
Нормализуются скриптом:

```bash
node scripts-normalize-apostrophes.mjs
```

Орфографически верны U+02BB и U+02BC, но в IBM Plex Sans их глифы нарисованы
как модификаторы шириной 24px при кегле 40 — шире буквы «o» (22.4px). Слово
`To‘liq` в них набирается как `To ʻ liq`. U+2018 в этой же гарнитуре — 10.92px
и правильной формы. При смене гарнитуры замер стоит повторить.

**Стрелки и галочки** — только inline SVG из `src/templates/icons.mjs`:
глифов `→` и `✓` нет ни в IBM Plex Sans, ни в IBM Plex Mono.

## Дизайн

Направление «ПРОТОКОЛ 01–17»: страница верстается как лист исполнительной документации —
белая бумага с зелёным подтоном, hairline-линии, сквозная моноширинная нумерация,
однолинейная схема как чертёж, фактура в формате «параметр : значение».

Правила, которые легко нарушить при доработке:
- фотография в разделе — иллюстрация под подписью, а не декор: кадра без подписи быть не должно;
- инверсия ровно одна (секция `#contact`), чередования полос быть не должно;
- радиусов три: `0`, `2px` (чипы), `6px` (кнопки и поля). Единый радиус на всём — маркер шаблона;
- вертикальные отступы секций — три разных токена, не один;
- рамки карточек — `box-shadow: inset 0 0 0 1px`, не `border`;
- бесконечных анимаций нет ни одной; бары анимируются `transform`, не `width`.

## Известное ограничение: узбекская версия и поиск

Узбекский текст лежит в атрибутах `data-uz` и подставляется скриптом — поисковик видит
только русский. Отдельных URL и `hreflang` нет. Это осознанный размен: без сборщика и сервера
второй языковой набор страниц удваивает объём генерации и ссылочную структуру.

Если узбекский трафик из поиска понадобится, минимальный вариант — генерировать второй
комплект страниц в `/uz/` из тех же данных (шаблоны это уже позволяют: язык передаётся
одним параметром) и связать пары через `hreflang`.

## Фотографии

Мастера лежат в `src/photos/`: `<slug>.jpg` — первый кадр раздела, `<slug>-2.jpg`,
`-3.jpg` и дальше — следующие. Имя совпадает со slug раздела, по нему шаблон сам
находит снимки. Веб-версии генерируются:

```bash
node scripts-photos.mjs
```

Скрипт делает до двух размеров в двух форматах (JPEG и WebP) и пишет манифест
`src/data/photo-sizes.mjs` — что реально получилось. Разметка берёт `srcset`
и `width`/`height` оттуда, поэтому не ссылается на несуществующие файлы
и не даёт сдвига вёрстки. Требуется `ffmpeg` (с `ffprobe`) и `cwebp`.

**Апскейла нет.** Берутся только стандартные ширины меньше оригинала плюс
native-ширина, если она даёт выигрыш больше 15 %. Растянуть 500-пиксельный
исходник до 1600 значит утяжелить страницу и получить мыло — деталей это
не добавит. В конце прогона скрипт печатает список кадров ниже 1600 px:
на десктопе они будут мягкими.

Подписи и alt-тексты — в `src/data/photos.mjs`, списком на раздел. Первый кадр
идёт во всю ширину, остальные — сеткой под ним. Раздел без записи в этом файле
выводится без фотографий, пустая рамка не появляется.

Пропорции в данных не задаются: они берутся из манифеста, то есть кадр
показывается таким, каким пришёл. Присланное клиентом нельзя обрезать
под общий формат, не выкинув половину смысла кадра.

**Про честность подписей.** Сейчас это иллюстрации типового оборудования,
и подпись под каждым кадром прямо это называет. Когда клиент пришлёт снимки
со своих объектов, достаточно заменить файл в `src/photos/` и переписать
`caption` — вёрстку трогать не нужно. Тогда же имеет смысл сменить метку
«Иллюстрация» на параметры объекта: что за объект, класс напряжения, что сделано.

Первые десять кадров приведены к одной обработке (`saturation=0.85, contrast=1.02`),
чтобы читались как снятые одним человеком. Присланные клиентом 19 кадров
эту обработку не проходили — см. следующий раздел.
